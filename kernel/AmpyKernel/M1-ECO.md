# AmpyKernel M1 — opt-in schedutil Eco experiment

GrapheneOS currently uses common kernel 6.1 plus device/vendor components for
Pixel 7 Pro. The source-based AmpyKernel M1 patch modifies **only two source
files** from the common kernel, when explicitly applied to reviewed commit
`a001019bb34ebe7b18cfc025b75a7550744a3e60`.

- Adds `CONFIG_AMPYKERNEL_SUGOV_ECO_DEFAULT` (Kconfig `default n`).
- When `y` **at build time**, starts each new schedutil policy with
  `rate_limit_us = max(driver_transition_delay_us, 2000us)`.
- Schedutil's normal `rate_limit_us` sysfs tunable remains available.
- When config flag is `n`, **the compiled governor behavior is unchanged**.
- Does not overclock, bypass thermal management, change max frequency,
  weaken SELinux, patch drivers, enable root or alter verified boot.

**This is a hypothesis, NOT an established battery improvement.** Increasing
the minimum governor update interval may reduce governor work but also hurt
application launch latency or responsiveness. This is best used as a controlled
benchmark, not enabled by default on a daily-use phone. Kernel.org documents
the `rate_limit_us` purpose and limits:
https://docs.kernel.org/admin-guide/pm/cpufreq.html

## Apply with provenance checks

```bash
# Download upstream complete kernel source in a Linux build environment:
bash scripts/prepare_kernel_sources.sh ~/src/kernel_pixel_6.1

# This pinned first patch may REFUSE the current 17 branch after updates:
python3 scripts/ampykernel_patch.py ~/src/kernel_pixel_6.1 --check

# Only if the matching kernel common revision is available:
python3 scripts/ampykernel_patch.py ~/src/kernel_pixel_6.1 --apply
# Undo this exact source diff:
python3 scripts/ampykernel_patch.py ~/src/kernel_pixel_6.1 --revert
```

If the source revision does not match the recorded commit and both recorded
file blob hashes, **stop and rebase/review the patch**. Re-applying it to a
moving branch without compatibility checks is not supported. The pinned OS
release `2026100600` was NOT verified to have this exact kernel commit.

## Enable the experimental setting

After patching, the Kconfig flag exists but defaults to **off**. A developer
must explicitly enable `CONFIG_AMPYKERNEL_SUGOV_ECO_DEFAULT=y` through the
kernel's maintained device configuration/fragment and check that the resulting
build's `.config` contains `CONFIG_AMPYKERNEL_SUGOV_ECO_DEFAULT=y`. Do not
assume editing an autogenerated `out/` config will persist; use the matching
Pantah Kleaf config/build infrastructure and review its defconfig fragments.

Then the official-compatible kernel build entry point is:

```bash
cd ~/src/kernel_pixel_6.1
KLEAF_REPO_MANIFEST=aosp_manifest.xml ./build_pantah.sh --lto=full
```

Per GrapheneOS instructions, only **after** a successful build with matching
vendor modules, ABI/security review and documented Pixel boot tests should a
full matching kernel artifact set replace
`device/google/pantah-kernels/6.1/grapheneos/` on a **separate development
ROM checkout**. DO NOT flash a bare kernel or cherry-pick modules across
releases.

## Baseline and evaluation

Compare *stock build (flag=n)* versus *Eco patch (flag=y)* under equivalent
screen brightness, environment, battery %, apps, workloads and network state,
with repeat runs. Capture reproducible:
- ADB `gfxinfo`/Perfetto FrameTimeline: frame latency, jank at 120Hz.
- App cold-start times and benchmark workload completion times.
- Android thermal statuses and sustained skin temperature.
- Energy usage (system battery meter isn't lab-grade; use controlled meter
  for trustworthy energy measurements).
- Idle drain over comparable multi-hour windows.

A useful safe fallback always exists: set `CONFIG_AMPYKERNEL_SUGOV_ECO_DEFAULT=n`
and rebuild. Keep thermal and safety protections enabled. The guard script
never flashes, signs or installs anything.

## Execute a read-only two-build comparison

```bash
# Capture these on the SAME cheetah phone with the SAME app/workload,
# once using a verified stock development ROM and once using a verified
# matching experimental development ROM. Do not run on unverified builds.
AMPY_APP_ID=dev.ampybios.core bash scripts/benchmark_cheetah.sh ./benchmarks/stock-01
AMPY_APP_ID=dev.ampybios.core bash scripts/benchmark_cheetah.sh ./benchmarks/eco-01

python3 scripts/ampykernel_benchmark_compare.py \
  ./benchmarks/stock-01 ./benchmarks/eco-01 \
  --out ./benchmarks/comparison.json
```

The comparator prints only metrics actually present. It never invents energy
savings, compares independent samples without caveats, flashes a device or
changes kernel settings. Repeat the comparison with controlled conditions.
